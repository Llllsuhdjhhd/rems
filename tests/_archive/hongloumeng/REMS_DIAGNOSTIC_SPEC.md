# REMS 记忆系统深度诊断测试规范与路线图

## 1. 运行环境 (Environment)
*   **语言环境**：Python 3.12.5 (Conda: `py3125`)
*   **存储引擎**：
    *   关系型数据库：SQLite (存储事件、角色、代谢状态)
    *   向量数据库：ChromaDB (存储基本事件摘要与角色白描)
*   **推理引擎**：DeepSeek-v4-flash (兼容 OpenAI 接口)
*   **核心框架**：REMS (Recursive Evolving Memory System) 1.0

## 2. 诊断执行标准 (Diagnostic Standards)

### 2.1 对 AI 执行者的要求
1.  **极致透明 (Extreme Transparency)**：
    *   凡涉及“原文”、“摘要”、“匹配项”的内容，必须直接导出原始变量字符串。
    *   **严禁摘要总结**：禁止对用户要求的“原文”进行任何二次概括。
2.  **全链路溯源 (Full Traceability)**：
    *   必须清晰展示：`[当前瞬时摘要]` -> `[向量检索词]` -> `[匹配到的历史白描]` -> `[最终拉出的完整事件]`。
    *   必须标注每一项匹配的 `Distance`（向量距离）或 `Score`（评分）。
3.  **零污染观测 (Non-intrusive)**：
    *   使用 `Runtime Hook` 捕获中间态，严禁在诊断过程中破坏生产流水线的原始逻辑。
4.  **编码规范**：
    *   所有报告强制使用 UTF-8 编码，彻底杜绝中文乱码。

### 2.2 数据格式定义
*   **残影 (Shadow)**：存留在系统缓冲区内、未经整理的 L0 原始文本素材。
*   **未完成事件 (Unclosed Event)**：存储已开启但未闭环的逻辑对象（包含已提取的角色与摘要片段）。

## 3. 测试进度与计划 (Milestones & Roadmap)

### Phase 1: 记忆召回增强验证 [已完成]
*   **验证项**：双流检索 (Stream A/B) 逻辑。
*   **核心优化**：成功验证了“基于瞬时摘要注入的增强型检索词”逻辑。
*   **结果**：实现了“摘要对摘要”的精准召回，显著提升了记忆与角色心境的契合度。

### Phase 2: 代谢与存续深度观测 [当前阶段]
*   **目标**：观察“生肉”文本如何转化为“结构化”记忆。
*   **核心实验**：
    1.  **边界探测 (Boundary)**：观察系统对叙事转折的切分敏感度。
    2.  **状态流转 (Lifecycle)**：实时跟踪 `Shadow -> Unclosed Event -> Sealed Event` 的流转。
    3.  **未完成库维护**：观察跨 Chunk 长叙事的逻辑拼接。
*   **数据要求**：一字不落展示每一轮的残影变化。

### Phase 3: 遗忘与静默逻辑验证 [待开启]
*   **目标**：验证系统的“生理性遗忘”与“检索屏蔽”功能。
*   **核心实验**：
    1.  **容量压力测试**：观察白描达到上限后的 `forgetting_factor` 衰减。
    2.  **静默阈值验证**：验证有效权重 < 0.02 时条目是否被正确从检索中物理忽略。

### Phase 4: 演化与抽象能力测试 [长期计划]
*   **目标**：观察系统从琐事中归纳高阶认知的能力。
*   **核心实验**：
    1.  **极大子集挖掘**：观察 `RecallLog` 触发抽象合成的时机。
    2.  **高阶认知生成**：验证 `L10/Insight` 层级的生成质量。
