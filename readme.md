# REMS 规范整理版

本文是在原始内容基础上做的 Markdown 排版整理，尽量不改动原意，仅提升可读性与结构清晰度。

## 1. 基本事件定义（修订版）

基本事件（Basic Event）是 REMS 中承载客观事实的最小记忆单元。基于最新的架构逻辑，基本事件不仅记录事实片段，还承载角色在当次事件中的瞬时状态（快照与情感），确保事件的可验证性与主体交互的完整性。

同时，本规范定义的属性集作为 REMS 事件实体的通用基准，兼容高阶抽象事件的扩展需求。

### 1.1 核心属性解析

#### 1.1.1 唯一标识与元数据

- `event_id`：全局唯一的字典序标识，确保系统内所有事件在全局范围内的唯一性、可区分性与可追溯性。
- `create_time`：记录事件封装完成的绝对时刻。

#### 1.1.2 原始数据属性

原始数据是基本事件的唯一数据底库，作为记忆系统生成、演化与追溯的绝对事实基准。

- `content_raw`：即 L0 级原始文本。
  - 基本事件：严格等于经 `BoundaryDetectionSkill` 剥离并判定为已完成的片段。
  - 抽象事件：由子事件的中位摘要合集集成生成的合成事实描述。
- 职能：后续所有层级的摘要、装饰及角色快照均以此为基准生成，作为验证衍生信息真实性的最高裁决标准。

#### 1.1.3 递归摘要体系属性

递归摘要体系是基本事件实现记忆轻量化与多尺度高效检索的核心，该体系设计为策略兼容型架构。

- `summaries`：以字典形式存储各级递归摘要（L1~Ln）。
- 多策略支持：可根据配置采用“固定比例压缩”“关键信息提取”或“语义改写”等模式。
- L1 级（核心事实种子）：实现最大化的“保真压缩”，剥离修饰语并严谨保留事实主干。
- 高阶层级（L2 及以上）：呈现渐进式的抽象梯度，支持基于语义重要性密度的动态截断。
- `summary_lengths`：以字典形式存储各级摘要对应的字符数，用于存储优化与检索预估。
- `actual_max_level`：受动态熔断机制（如少于 20 字）约束的实际生成层级。

#### 1.1.4 角色交互与瞬时状态属性

通过 `role_list` 记录当次事件中所有参与者的交互细节及量化快照。

- `role_list`
  - `role_id`：关联至角色系统的唯一 ID。
  - `importance`：`S/A/B/C/D` 五级分级。
  - `role_snapshot`
    - L1（提及快照）：仅记录角色是否出现或被提及。
    - L2（互动快照）：描述角色的核心行为、言论及社交关联，白描系统默认拉取此项。
    - L3（决策快照）：聚焦记录角色的核心决策逻辑、行为倾向及客观意图。在抽象事件中，此项用于建立“性格倾向”视图，并提供快速调用原始白描片段的途径。
  - `emotional_model`
    - 五受量化（Vedana）：乐、苦、喜、忧、舍。
    - 六根本烦恼量化（Klesha）：贪、嗔、痴、慢、疑、恶见。

#### 1.1.5 抽象演化与生命周期标记

- `is_abstract`：架构级常量。基本事件固定为 `False`，抽象事件固定为 `True`。
- `is_abstracted`：演化状态位，记录该事件是否已被高阶认知逻辑吸收。
- `status`：反映事件在回忆系统中的权重（未闭环 / 活跃 / 静默）。

#### 1.1.6 扩展属性与规律内核

- `decoration`：针对 `content_raw` 的非事实性描述（色彩、空间感、哲学映射），支撑“梦见”系统的非线性关联。
- `insight`
  - 基本事件：固定取值为 `None`，严格执行物理隔离，防止事实层产生“伪规律”污染。
  - 抽象事件：存储该演化过程产生的实质性规律、见解或逻辑推导结论。

#### 1.1.7 事件长度约束属性（修订）

- `event_length`：记录 L0 级原始文本的字符长度。
- 物理防御约束：最高上限设定为 `1/66 * Context_Window`。
- 逻辑职能：仅在面对复杂长片段时进行颗粒度控制；对于逻辑简单的短小事件，其实际长度应根据客观情况自然收缩，不强制填充。

#### 1.1.8 抽象事件专用扩展属性（基本事件缺省）

本小节定义的属性仅在 `is_abstract == True` 时生效，基本事件无需包含此类字段。

- `abstraction_level`：记录该事件在递归演化树中的深度。
  - L1 级：由基本事件归纳而来的初级规律。
  - Ln 级：由低阶抽象事件再次聚合而来的高阶逻辑。
- `source_events`：存储支撑该抽象节点生成的全部子事件 ID 列表。
- 职能：建立从“抽象规律”到“原始证据”的溯源链条，支撑角色属性的快速下钻调用（Fast Access Path）。

## 2. 角色系统定义（修订版：全局 ID 与时间线白描系统）

角色系统（Role System）是 REMS 中管理持久化实体信息的独立模块。其核心职能是维护全局唯一的角色标识（`role_id`），并将分散在不同基本事件中的该角色相关事实按时间顺序进行收集与汇编，形成该角色的“白描轨迹”。

### 2.1 角色标识与独立性（Standalone Role Identity）

- 独立性定义：角色 ID（`role_id`）是系统内绝对独立的全局标识符，不随特定事件的消亡或抽象而改变。它是一个持久化的“容器指针”，用于归集该实体在系统生命周期内产生的所有行为记录。
- 角色定义边界：角色指在不同事件中可被清晰识别、区分且具备持续观测价值的实体。
  - 命名实体：如特定的人、具备独立特征的动物（如 `ROL-001 赛虎`）。
  - 特定物体：具备唯一历史属性或交互价值的器物（如 `ROL-005 和氏璧`、`ROL-009 太阳`）。
- 去代词化映射：角色系统强制要求在所有外部输入转化为基本事件的过程中，通过 `role_id` 替换所有模糊代词，确保数据在底层收集时的绝对指向性。

### 2.2 角色白描系统（Chronological White-painting System）

角色的白描（White-painting）是对属于同一角色 ID 的所有事件片段按时间轴（Timeline）进行的客观收集与串联。

#### 2.2.1 收集与汇编逻辑

- 跨事件汇编：角色系统会实时或在后台检索全量基本事件。每当一个基本事件包含某个 `role_id` 时，系统便会将该事件中关于该角色的“瞬时记录”拉取到该角色的白描轴中。
- 时间序排列：白描记录严格按照事件的 `create_time` 进行升序排列，形成一个无主观推演的、流水账式的角色自传。

#### 2.2.2 单条白描条目的构成（Entry Structure）

白描轴上的每一个节点（条目）均由当次事件的特定属性构成，确保“白描-事件”的统一与可追溯：

- 事件关联（Event Reference）：记录对应的 `event_id`，通过白描，系统必须能够实现“一键跳转”回原始基本事件。
- 角色摘要（Role-Event Summary）：默认采用当次事件中该角色的 L2 级（互动快照）摘要信息，记录角色在当次事件中的具体行为。
- 糅合情感（Blended Emotions）：记录角色在当次事件中的瞬时情感状态（五受与六根本烦恼的量化矢量），反映角色随事件变迁的心理波动轨迹。
- 参与等级（Role Importance）：记录角色在当次事件中被评定的重要程度（`S/A/B/C/D`），决定该条白描在角色演化评估中的权重。

### 2.3 后台处理与索引职能

- 后台自动化处理：角色白描的更新通常由后台任务执行。当基本事件完成封装后，系统触发角色同步技能，将快照和情感数据分发至对应 `role_id` 的白描库中。
- 双向关联索引：
  - 从角色到事件：通过 `role_id` 的白描轴，可以直接关联并访问该角色参与的所有历史事件。
  - 从事件到角色：基本事件通过 `role_list` 链接至角色系统获取该角色的全局定义。

### 2.4 角色系统的应用职能

- 角色视角的回忆：允许系统以“某人 / 某物经历了什么”为维度进行记忆提取，而非仅以“发生了什么”为维度。
- 实体一致性维护：确保同一实体在不同事件中的描述不产生逻辑冲突（如身源信息、固有属性）。
- 支持梦见与抽象：为更高维度的抽象事件提供基于角色的规律素材，例如分析 `ROL-001` 在过去 10 次事件中“贪”的程度演化。

## 3. 抽象事件定义规范

抽象事件（Abstract Event）是 REMS 中实现记忆升华、规律提取与长效压缩的核心载体。它通过对多个基本事件（或低阶抽象事件）的归纳与演化，形成具备跨时间、跨角色属性的高阶认知节点。

为了确保递归演化的兼容性，抽象事件在数据结构上与基本事件保持完全一致的属性集，仅在关键逻辑处体现其特殊性。

### 3.1 核心属性解析

#### 3.1.1 元数据属性

- 标识与时间：`event_id` 与 `create_time` 的定义与基本事件一致。
- `abstraction_level`：记录在递归树中的深度（L1 为初级规律，Ln 为由抽象事件再次聚合的高阶规律）。

#### 3.1.2 原始数据属性（合成事实层）

- `content_raw`：并非外部输入，而是由大模型基于关联事件集（`source_events`）生成的合成事实。
- 层级选取机制：支持自主设置并选择取用子事件的某一级摘要（默认中位层级 L3）作为合成基础。
- 职能：作为抽象节点唯一的原始逻辑底库。

#### 3.1.3 递归摘要体系属性

- 摘要逻辑：`summaries` 与 `summary_lengths` 结构与基本事件一致。
- 特殊基础：其摘要生成是以“选定层级的摘要合集”为逻辑起点，旨在剥离细节冗余，保留核心逻辑事实的密度。

#### 3.1.4 角色交互属性（逻辑投影与视图聚合）

抽象事件不具备对角色白描系统的“写入权”，仅提供聚合视图。

- `role_snapshot`
  - L3（决策快照）：记录角色在该抽象规律下的典型决策风格与逻辑倾向，而非单次行为。
- Fast Access Path：建立虚拟映射，允许系统通过 `source_events` 秒级下钻定位并重组该角色在对应基本事件中的原始白描轨迹。
- 情感模型：记录该规律覆盖范围内角色情感的统计特征或平均趋向。

#### 3.1.5 状态与演化标记

- `is_abstract`：固定为 `True`。
- `is_abstracted` 与 `status`：逻辑与基本事件一致。

#### 3.1.6 规律内核属性

- `decoration`：定义与基本事件一致，提供宏观认知的文学性修饰。
- `insight`：不同于基本事件的缺省，此处存储实质性的规律见解、逻辑推导或顿悟结论。
- `source_events`：存储支撑该节点生成的全部子事件 ID 列表，是溯源与快速调用的逻辑纽带。

#### 3.1.7 长度与防御约束

- 物理红线：长度统计与 `1/66` 上下文上限约束与基本事件完全一致。

### 3.2 抽象事件的触发机制

- 召回聚集触发（Recall Cluster Trigger）：当本次输入封装为基本事件后，若关联逻辑点召回历史事件数量超过 5 个，则启动归并分析生成抽象事件。
- 演化驱动触发：定期扫描未被吸收的基本事件，属于低频维护机制。
- 手动演化触发：通过特定指令强行总结语境规律。

### 3.3 与角色系统的关联

- 白描主权原则：白描轨迹仅由基本事件更新。
- 抽象事件仅通过 `event_id` 链条进行“引用”与“重组呈现”，确保不产生事实冗余。
- 演化反馈：向涉及角色的白描系统反馈性格偏移评估（如贪、嗔等维度的趋势分析）。

## 4. 事件代谢素材与触发机制规范

事件代谢素材与触发机制是递归演化记忆系统（REMS）的核心动力层。通过规范输入、残影、回忆块的物理属性及其触发、拼接规则，确保系统在有限的上下文窗口内实现逻辑的无限连续性。

### 4.1 基础属性定义

#### 4.1.1 输入定义与长度属性（Raw Input & Length）

输入是系统接收的外部增量信息，是驱动事件生成的直接素材源。

- Raw Input：系统接收的原始增量文本信息，不包含历史回忆与残影。它是基本事件原始数据（`content_raw`）的核心活跃来源。
- 物理长度约束：单次新增输入的长度受系统全局阈值 `len_msg` 的硬约束，确保单次输入规模处于系统可控范围内，防止因单次信息量过载导致上下文溢出。
- 量化标准：默认比例阈值设定为当前大模型上下文窗口（Context Window）的 `1/66` 左右。
- 独立性声明：`len_msg` 阈值是专门针对输入阶段设立的独立物理参数。尽管其默认取值与基本事件长度约束比例一致，但逻辑上完全解耦，分别服务于“输入准入控制”与“事实存储颗粒度控制”两个不同环节。
- 配置职能：该阈值支持全局设定，用于在输入源头控制事实片段的颗粒度，确保代谢素材包的整体规模符合系统的物理防御要求。

#### 4.1.2 残影与未完成事件库（Shadow & Unclosed Event Library）

系统同步维护“残影”与“未完成事件库”，分别管理原始素材与逻辑半成品，通过双轨运行实现代谢效率的最大化。

- Shadow：存留在系统缓冲区内、未经整理的原始文本内容，本质上是一个“素材待处理区”。
  - 包含当前大模型判定为“无法提取出完整事件”的所有文本片段。
  - 也包含部分由于篇幅过短而暂缓封装的完整事实碎片。
- Unclosed Event Library：系统维护的独立逻辑仓库，用于存储经大模型分析确认为“已开启但未闭环”的事件逻辑对象。
  - 每一个未完成事件均包含已识别的事实片段、待补全的逻辑缺口及关联角色。

代谢与归入逻辑如下：

- 内容剥离与删除：在封装逻辑中，大模型扫描 `Shadow + Input`。一旦识别出“完整事件”，该内容立即从残影中彻底删除。
- 精准归入机制：当新增输入涉及的内容被判定为属于库中某个“未完成事件”的延续时，系统将其直接归入该逻辑对象，更新其状态而非重新生成。
- 新事件生成：
  - 若输入包含完整且独立的新事实，则触发新基本事件的生成流程。
  - 若属于新开启但未闭环的事实，则在库中新建未完成事件记录。

双实体隔离原则：

- `Shadow`：纯粹的原始文本实体，作为未被消化的原始数据湖。
- `Unclosed Event`：独立的逻辑实体。
- 系统不会为了迎合其逻辑定义而更改残影的原始性质。

物理防御触发与遗忘机制：

- 物理红线设定：系统设置最高物理安全边界，其取值为模型当前上下文窗口的 `1/6.6`（约 `10/66`）。
- 强制封装逻辑：当系统资源触及物理红线，或特定“未完成事件”积累的原始文本长度达到基本事件长度标准的 `0.8` 倍时，系统启动强制封装。
- 短事实固化：在此阶段，所有原先因篇幅过短而留存在残影中的完整事实，必须被强制提取并归档为基本事件。此类内容具备“绝对存储主权”，严禁被遗忘或丢弃。
- 长期未击中遗忘逻辑：针对长期未被新输入激活（未被击中）的“未完成事件”（非完整事实），系统执行定期清理。
  - 若该未完成事件涉及特定角色（拥有 `role_id`），系统会将该事件的残余信息作为一条“任务 / 轨迹白描”追加至该角色的白描系统。
  - 在完成白描追加或确认无角色关联后，该未完成事件将从库中彻底删除（遗忘）。
- 目标回落水位：通过上述强制封装与遗忘机制的协同作用，系统必须确保执行后的活跃残影与未完成事件库所占用的上下文规模回落至全局安全水位，默认比例为 `2/66 * Context Window`。

### 4.2 事件的触发（Event Trigger）

事件触发决定了代谢素材包何时从“流式输入”状态转入“封装处理”状态。

- 逻辑闭环触发（语义触发）：这是系统最高优先级的自动化触发机制。当大模型判定其中包含逻辑完整、已闭环的事实（即判定 `Is_Completed = True`）时，系统原则上立即启动封装流程。
- 短片段留存策略：若该完整事实篇幅极短且逻辑过于简单，为避免产生过多碎片化事件记录，系统可允许其暂时留存在残影（Shadow）缓冲区中，等待后续关联信息的补充或合并。
- 长度触发（水位触发）：当特定“未完成事件”及其关联素材的累积长度达到系统全局配置阈值 `len_msg`（`1/66 Context`）时，即使逻辑尚未整体闭环，系统也会自动激活基本事件生成流程。
- 中间截断机制：在大模型引导下，系统会寻找语义相对完整的逻辑断点，执行约 `0.8 : 0.2` 的比例截断。
  - 截断出的 `0.8` 部分被封装为“完整事件”并存入事件系统，同时从残影中剥离。
  - 剩余约 `0.2` 部分作为新的“未完成事件”保留在未完成事件库中并留存在残影内，以维持上下文的动态代谢。
- 手动指令触发：当系统接收到预设的手动指令（如 `/save`、`/mem`）时，具备最高优先级。系统将立即中断当前对话 / 任务逻辑流，强制执行当前输入、残影与关联素材的封装。

### 4.3 抽象事件的触发（Abstract Event Trigger）

抽象事件触发负责将孤立的基本事件提升为更高维度的认知规律。

- 召回聚集触发（Recall Cluster Trigger）：
  - 系统首先将本次输入的内容封装为独立的基本事件（Basic Event）。
  - 封装完成后，若该事件关联的某一个特定逻辑点所召回的历史基本事件数量超过 5 个，则系统判定该语义主题已达到聚集阈值。
  - 此时系统自动对这些已固化的基本事件进行归并分析，生成新的抽象事件（Abstract Event），实现记忆的结构化升级并优化后续召回效率。
  - 该机制严禁直接在原始输入素材上进行抽象，必须确保事实先入库再演化。
- 演化驱动触发（低频维护机制）：系统定期监测 `is_abstracted == False` 的基本事件。当未被收录的基本事件涉及特定角色或相似语义的频率达到阈值时，触发 `InductiveEvolutionSkill`。该机制作为系统自我整理的兜底逻辑，在实际运行中处于低频状态。
- 手动演化触发：用户可以通过特定指令引导系统针对当前已生成的多个基本事件进行深度总结与抽象。

### 4.4 回忆块（Recall Block）

回忆块是系统基于当前语境召回的历史背景素材，用于保障事件逻辑的连贯性。

- 定义与来源：回忆系统以输入与残影为检索依据，通过角色标识、分级及语义关联，从事件系统、角色系统（及其角色的时间轴白描轨迹）、梦见系统中召回相关事实与内容集合。
- 物理防御红线：回忆块长度严格遵循 `1/6.6` 上下文主权约束。
- 配额公式：`Size in [0, 10 * len_msg]`，即上限为上下文窗口的 `1/6.6`。

若召回内容超限，系统执行以下显著性剪枝与配额控制流程：

- 相关性综合评分（Hybrid Relevance Score）：
  - 语义关联度：输入 / 残影与历史事件内容的余弦相似度。
  - 角色显著性：涉及角色的重要性分级（S 级权重最高）。
  - 时间衰减指数：基于遗忘曲线对较早事件进行自然降权。
- Lazy Index 动态降级策略：
  - 默认层级：回忆块初始召回默认采用事件自身“层级长度”的中位层级（例如层级长度为 5 时默认用 L3），在空间充裕时向上探测 L1。
  - 降级阶梯：摘要层级按 `L1 -> 中位层级 -> 最大摘要层级` 顺序逐级压低。
  - 保护机制：对于高重要性角色的核心决策快照（L3），具备降级豁免优先级。
- 极简摘要映射（Ultra-concise Summary Mapping）：
  - 若摘要已全部压至最大层级且召回块总长度仍超过 `1/6.6` 限制，系统严禁直接剔除事件。
  - 此时启动“简化摘要”模式，将事件单元压缩至极致物理规模。
  - 呈现形式：仅保留 `Event_ID + 核心动词/关键谓语 + 涉及角色 ID` 的三元组形式。
  - 逻辑职能：这种极简映射作为一种“感知残留”，仅占用极少 Token 资源，同时保留通过 `Event_ID` 反向索引深度事实的可能性，避免因“硬剪枝”导致记忆链路彻底断裂。
- 召回一致性验证：每一次剪枝或降级后，系统需重新统计 Token 规模，确保最终输出严丝合缝地契合物理防御红线。

### 4.5 拼接和呈现（Context Package Protocol）

拼接和呈现定义了代谢素材包在交付给判定组件前的物理组合协议。

- 拼接顺序协议：遵循“历史参考 -> 原始残影 -> 当前输入”的逻辑顺序。
- 结构：`Recall Block + Shadow + Current Input`。
- 拼接策略插槽：系统预留自定义插槽，允许根据不同领域需求切换拼接逻辑。
- 呈现职能：拼接后的代谢素材包作为 LLM 的当前 Context 输入。大模型通过对比“未完成事件库”中的索引，识别“归入”或“生成”行为。
- 被封装的部分从残影缓冲区抹除，未闭环部分继续以原始文本形式保留在残影中，其逻辑状态同步更新至未完成事件库。
- 当触及物理红线或达到 `0.8` 封装标准时，优先执行强制保存，并确保清理后的规模回落至 `2/66` 水位。
